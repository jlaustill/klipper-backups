# Voron 2.4r2

## 0. System Architecture (Mental Model)

**This separation is sacred — do not blur it.**

| Function        | Device                               | Why                                    |
| --------------- | ------------------------------------ | -------------------------------------- |
| Z = 0 reference | Frame-mounted Klicky (Omron D2F-01F) | Absolute, repeatable, thermally stable |
| Bed shape       | Eddy Duo                             | Dense, fast, contactless               |
| Transport       | Native CAN (Octopus Pro ↔ EBB42)     | Clean, low noise                       |
| Timing          | Mesh after bed heat                  | Eliminates drift concerns              |

🚫 Eddy **never**:

* Homes Z
* Sets Z offset
* Acts as endstop
* Decides nozzle height

Eddy answers **one question only**:

> “What is the *shape* of the bed right now?”

---

## 1. Flashing Order (Do This Before Wiring Anything)

### 1️⃣ Flash Octopus Pro (Enable CAN)

* Flash Klipper **with CAN enabled**
* Use native CAN pins on the Octopus Pro
* Confirm CAN interface comes up (`can0`)

You want:

```
ip link show can0
```

✅ Present = good
❌ Missing = stop and fix before continuing

---

### 2️⃣ Flash EBB42 for CAN

* Flash **Klipper CAN firmware**
* Do **not** connect USB afterward
* Power via CAN + 24V only

Verify discovery:

```
ls /dev/serial/by-id/
```

or

```
~/klippy-env/bin/python ~/klipper/scripts/canbus_query.py can0
```

You should see **exactly one UUID** for the EBB42.

---

## 2. Wiring (Minimal, Clean, Nothing Extra)

### CAN Wiring

* CAN H → CAN H
* CAN L → CAN L
* Twisted pair (don’t overthink it)
* Ground shared via power harness

### Power

* 24V → EBB42
* Eddy powered **through EBB42**
* No USB power
* No I2C
* No secondary ground hacks

### What You Do *Not* Wire

* ❌ Eddy to Octopus directly
* ❌ Eddy USB
* ❌ Eddy I2C
* ❌ Eddy Z endstop pins

If a pin isn’t needed for **CAN or power**, it stays empty.

## 3. Klipper Config (Only What You Need)

### MCU Definitions

```ini
[mcu]
serial: /dev/serial/by-id/usb-Klipper_stm32f446xx_XXXXXXXX-if00

[mcu ebb42]
canbus_uuid: YOUR_EBB42_UUID
```

---

### Klicky (Z Endstop Only)

```ini
[stepper_z]
endstop_pin: ^PA2   # example — use your actual Octopus pin
position_endstop: 0.0
```

Z offset is set **once**, mechanically verified, and never touched again unless hardware changes.

---

### Eddy (CAN Mode, Mesh Only)

```ini
[eddy]
sensor_type: btt_eddy
canbus_uuid: YOUR_EBB42_UUID
x_offset: <measure this>
y_offset: <measure this>
```

That’s it.
No Z logic.
No homing overrides.
No compensation tables.

---

### Bed Mesh (Accuracy-First)

```ini
[bed_mesh]
speed: 120
horizontal_move_z: 5
mesh_min: 30,30
mesh_max: 270,270
probe_count: 9,9
algorithm: bicubic
fade_start: 0.8
fade_end: 5.0
```

**Why these values**

* 9×9 is already *very* dense for Eddy
* Bicubic plays nicely with smooth inductive data
* Fade avoids over-correcting higher layers

You can go 11×11 later if you feel spicy — you won’t need to.

## 4. Calibration Sequence (Do Not Reorder This)

### 1️⃣ Mechanical Z First (Once)

* Home Z using Klicky
* Set Z offset
* Paper test or feeler gauge
* Lock it in

You should **never touch Z offset again** unless:

* Nozzle changes
* Klicky geometry changes

---

### 2️⃣ Eddy Sensor Calibration (Once)

Run:

```
EDDY_CALIBRATE
```

* Bed at **printing temperature**
* Toolhead at **normal ambient**
* Let it finish
* Save config

This teaches Eddy *what metal looks like*, not where Z=0 is.

---

### 3️⃣ Mesh Validation

```
BED_MESH_CALIBRATE
```

* Watch for smooth gradients
* No sudden cliffs
* Save *nothing* permanently

---

## 5. Print Flow (Every Print, No Exceptions)

Here’s the **correct startup logic**:

1. Heat bed
2. Wait for bed temp to stabilize
3. Home X/Y
4. Home Z (Klicky)
5. Run Eddy mesh
6. Print immediately

---

### Example START_PRINT Macro (Opinionated)

```ini
[gcode_macro START_PRINT]
gcode:
    M140 S{params.BED}
    M104 S{params.HOTEND}
    M190 S{params.BED}
    G28 XY
    G28 Z
    BED_MESH_CLEAR
    BED_MESH_CALIBRATE
    M109 S{params.HOTEND}
```

No mesh loading.
No reuse.
No thermal assumptions.
